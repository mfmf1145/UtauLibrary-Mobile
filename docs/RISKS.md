# 风险提示

按重要程度排列。每一条都对应程序内的提示或防护。

## 1. OpenUtau Mobile 本身非常不稳定（最高优先级）

官方 README 原文：

> OpenUtau Mobile is **very unstable**... memory management issues may occur frequently... **remember to save often**.

- 崩溃可能造成工程数据丢失。
- 程序在首次启动引导、设置页风险区都明确提醒「频繁保存」。
- 崩溃后可在工程同目录寻找 `.autosave.ustx` 恢复文件。
- 建议：安装/删除大体积声库前后先保存工程并退出编辑界面。

## 2. SAF 路径授权失败 / 无法授权到默认目录

- OpenUtau Mobile 的数据根目录是**应用私有目录** `/data/user/0/pers.vocoder712.openutaumobile/files/`
  （声库 `files/Singers/`，插件与音素器共用 `files/Plugins/`）。
- 应用私有目录**第三方程序无法直读**，SAF 也授权不到；除非有 root / Shizuku / ADB 权限。
- **无需 root 的可行方案**：在 OpenUtau Mobile 设置里启用「额外歌手路径」并指向共享存储目录
  （例如 `/storage/emulated/0/OpenUtau/Singers`），本程序再对同一目录做 SAF 授权。
- 部分 ROM 的第三方文件管理器不会返回可持久化 URI 授权，表现为重启后失效；请改用系统自带「文件」App。
- 授权失效后目标目录会写入失败，程序会提示「SAF 授权可能已失效，请重新授权」。

## 3. GitHub API 限流

- 未认证：Search API 约 **10 次/分钟**，Core API 约 **60 次/小时**。
- 音素器检索会连续调用一次 search + 每个仓库一次 releases，很容易触发限流。
- 程序会在界面显示限流错误并引导用户到「设置」填入自己的 GitHub Token（认证后 30 次/分钟、5000 次/小时）。
- 本清单的检索是**实时**的，网络不通或限流时列表可能为空，这不代表程序故障。

## 4. 直链失效

- 声库与插件是手动收录的官方直链，作者随时可能更换发布方式、删除 Release 或改用网盘。
- 程序在下载失败时提示「直链可能已失效或网络不可达」；`assets/resource_manifest.json` 可直接编辑维护。
- 建议定期校验并按 `docs/BUILD.md` 重新打包。

## 5. 国内网络状态标记（🟢🟡🔴）的维护成本

- 该标记是**人工维护**的静态字段，不会自动更新；网络状况会随时间变化。
- 内置清单中的 GitHub Releases 直链统一标为 🟡（直连缓慢），这是保守默认值。
- 需要重新校准时可在程序内做一次探测后覆盖缓存（`AppSettings.lastNetworkProbeAt`）。
- 🔴 资源会在卡片上显著标红，并在下载确认弹窗中再次提示，避免用户点了卡住。

## 6. 音素器在移动端可能不兼容（重点）

- OpenUtau Mobile 的插件/音素器加载流程：枚举 `Plugins/` 下所有 `*.dll` → 校验是否为**托管 .NET 程序集** → `Assembly.LoadFile` → 反射 `Phonemizer` 子类。
- 结论：**支持托管 .NET DLL，不支持原生 Windows/C++ DLL**（会直接被跳过）。
- GitHub 上多数 `openutau phonemizer` 仓库发布的是桌面原生 DLL，移动端很可能无法加载。
- 程序仍然按需求收录并给出醒目标注，不隐藏、不禁用，但用户需自担兼容性风险。

## 7. 旧式 UTAU 插件的 .exe 在安卓上无法运行

- UTAU 旧式插件（`plugin.txt` + `.exe`/`.bat`）依赖 `Process.Start` 启动外部程序，移动端不可用。
- 程序对这类条目标注「安卓无法运行」，但仍允许下载以便用户在自己的桌面环境使用。

## 8. 解压相关的风险

- 已实现的防护：路径穿越（zip-slip）拦截、跳过 `__MACOSX`、条目数上限 200000、解压总大小上限 6GB。
- RAR 支持基于 junrar，RAR5 的兼容性有限；加密压缩包（AES-256）**不支持**。
- 若解压后无法自动识别目录结构，程序会进入「等待确认」状态而不是乱写文件。

## 9. 存储空间

- DiffSinger 声库单个体积常在 300–650MB，解压后可能翻倍；安装过程需要临时空间。
- 程序在应用缓存目录完成下载与解压，安装成功后自动清理临时目录。

## 10. 许可证

- 内置清单中各声库/插件的授权各不相同（有的禁止商用、有的禁止修改）。
- 程序只做链接与安装，不重新分发；使用前请自行确认原始条款。
- junrar 的许可源自 UnRAR restriction，详见 `THIRD_PARTY_NOTICES.md`。

## 11. 实测：网络线路的真实情况（2026-10，本机网络）

| 目标 | 结果 |
| --- | --- |
| github.com 直连 | 连接超时（完全不通） |
| gh-proxy.com 加速 | 200，约 191 KB/s（可用） |
| ghproxy.net 加速 | 200，约 85 KB/s（可用） |
| ghfast.top / mirror.ghproxy.com / gh.llkk.cc | 不通 |
| kasaneteto.jp 单连接 | 482 KB/s |
| kasaneteto.jp 4 线程分块 | 约 230 KB/s（反而更慢，按连接限速） |

结论与对策：
- GitHub 资源必须走加速线路，否则会一直卡到超时 —— 程序内置自动切换；
- 多线程并非总是更快，部分站点按单连接限速 —— 默认关闭多线程，可在设置里开启对比；
- 加速前缀是第三方服务，可能随时失效或被限速，属于外部依赖，请以实测为准。

## 12. 实测：多线程分块下载是负优化（2026-10-11）

机内自检（Download/UtauMarketMobile-download.log，HONOR DNP-AN00 / Android 16）
对 https://kasaneteto.jp/assets/download/utau/TETO-jakuongen210725.zip 的实测：

| 模式 | 结果 |
| --- | --- |
| 单连接 | 803 KB/s，峰值 2688 KB/s |
| 4 线程分块（Range 并发） | 约 70 KB/s（7 秒几乎没进展） |
| 对照：curl 单连接 | 972 KB/s |
| 对照：OkHttp 同循环（沙箱） | 630 KB/s |

结论：该服务器对多连接 Range 请求**惩罚性限速**，多线程比单连接慢约 30 倍。

由此引出的两个次生 bug（均已修复）：

1. 分块必须先把文件 setLength(total) 预分配成完整长度，导致文件长度不再等于已下载字节数，**进度条失真**；
2. 暂停/继续时按文件长度判断进度，空洞文件被当成“已下完”，拿去解压就报
   **“解压失败：压缩包可能损坏或格式不受支持”**，而且会一直复现。

修复：

- 彻底移除多线程分块，恒用**单连接 + HTTP Range 断点续传**；
- 续传前校验半成品头部魔数（PK/Rar/7z/gz），不是压缩包就丢弃重下；
- 下载完成后再次校验：若是 HTML 明确提示“直链已失效”，否则提示“下载被截断”；
- 启动时一次性清理旧的预分配半成品缓存。

## 13. 实测：多线程对不同站点的效果完全相反（2026-10-11）

同一台手机、同一时间窗口，对声库各个来源实测（KB/s）：

| 来源 | 声库数 | 单连接 | 4 线程 | 结论 |
| --- | --- | --- | --- | --- |
| gh-proxy.com（GitHub 加速） | 28 | 278 | **1192** | 4.3×，必须多线程 |
| zunko.jp | 11 | 282 | **840** | 3.0× |
| www.canon-voice.com | 9 | 115 | **845** | 7.3× |
| hf-mirror.com | 5 | 慢/不稳 | — | 链接有效但慢 |
| kasaneteto.jp | 11 | **803** | 70 | 0.09×，惩罚多连接 |

因此下载器改为**按站点自适应**：默认 4 线程；某站点试跑 4 秒拿不到 400KB 就判定它惩罚多连接，
回退单连接并把该站点记进 SharedPreferences，以后直接用单连接。

上一版多线程翻车的两个根因（已修）：
1. `setLength(total)` 预分配文件长度 —— 进度条失真、暂停后被误判为已下完、解压失败；
2. 断点续传依赖文件长度 —— 分块写入的文件长度不等于已下载字节数。
现在分块进度靠旁路 `<file>.part.meta` 逐块记录，完成判定用各块之和，绝不看文件长度。

另：手机网络本身波动极大（同一 URL 不同时刻 133 KB/s ～ 972 KB/s），
所以界面上显示的速度做了指数平滑，避免数字乱跳。


> 另：11 条重音テト直链已逐条验证，均返回合法 zip（content-type: application/zip），链接本身没问题。
